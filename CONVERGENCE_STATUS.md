# Convergence Status

Last updated: 11 August 2026

This document records verified implementation status on the `convergence` branch. A phase is complete only when its live integration, failure handling, lifecycle cleanup, protocol compatibility, focused tests, and full-solution validation have been demonstrated.

## Baseline

- `origin/game_rework` at `dade7f0d` was merged into `convergence` without rewriting published history.
- The merge moved the repository to `Source/NexusForever.slnx` and retained both convergence test projects.
- Build-16042 community privacy wire values remain encoded in one bit as `Public = 0` and `Private = 1`.
- The full solution builds and all current automated tests pass. The offline archive reader now uses a source-maintained, patched SharpCompress integration with real build-16042 LZMA coverage and no reported vulnerable packages.

## Security and stability

Completed hardening:

- Bounded inbound game packets, bounded nested packed packets, and fail-closed game-packet dispatch.
- A per-session bounded asynchronous writer serialises complete game and STS frames, handles partial sends, applies byte/frame backpressure without blocking the world thread, and makes disconnect/drain state atomic.
- Bounded STS headers, bodies, SRP fields, and XML parsing, including correct fragmented and coalesced packet handling.
- Enforced STS authentication states with a pending state, authenticated-only token/account operations, and same-connection reauthentication support.
- Session encryption keys and account credentials are no longer written to authentication logs or exceptions.
- World shutdown awaits every player save, attempts both databases and every connected player after individual failures, and reports aggregate failure before declaring shutdown complete.
- Map updates isolate and report individual top-level map and instance failures in both synchronous and worker-task modes, allowing healthy siblings to keep ticking.
- Character and Account service APIs require bounded per-service credentials; typed clients attach them without redirect forwarding, and Aspire provisions separate persisted secrets.
- The administrative command WebSocket is disabled by default, bound to loopback in the example configuration, and no longer published by the default Aspire topology. When explicitly enabled it requires a hashed bearer credential and exact Origin and permission allow-lists, accepts only bounded strict-UTF-8 text messages, bounds the global delayed-command queue, and serialises bounded per-connection responses through one observed writer.
- Task-backed events now distinguish successful, failed, and cancelled operations. Authentication and character mutations fail closed without running success callbacks, detached task failures are logged by default, and player cleanup retains its account lock while retrying failed saves.
- World loot tables now have an EF migration, are validated and loaded recursively at startup, and active loot expiry advances from the world tick. Invalid graph, probability, or count-range data fails startup without poisoning a later initialisation attempt; timed and stale removals clean every index and retire the build-16042 owner-scoped client view.
- Player saves are serialised and acknowledge Auth and Character commits independently. Player/account state, inventory, mail, character stats and scalar progression, presentation and loadout graphs, quests, achievements, keybindings, entitlements, RBAC, guilds, and housing retain dirty state and deletion tombstones until their database commit succeeds; manager shutdown retries failed saves without blocking worker threads.
- Loot claims validate the stable character identity, client-supplied owner/item identifiers, live source entity, exact map instance, and range. Inventory-full claims remain retryable, reward-path failures use an at-most-once boundary, and unsupported loot-table item types fail startup rather than leaving permanent uncollectable drops.
- Quest reward selection, eligibility, currency/reputation/XP bounds, and aggregate inventory capacity are validated before mutation; pushed-item removal and item grants use one exact-bag exchange and repeated or re-entrant completion is rejected.
- Proc trigger chance, internal cooldown, event-target routing, deferred execution, exact effect identity, lifecycle cancellation, and proc-origin recursion suppression are validated against build-16042 spell data.
- Base caster/target vital requirements and aliased player resource costs are revalidated atomically at spell execution; failed admissions clean up without leaking pending spells, and channelled costs are charged per successful pulse.
- Eligible spell-effect rows in one activation batch aggregate both cost slots by canonical vital, preflight and consume once before any handler, and fail/cancel with rollback of every deterministically committed earlier cost. Zero-target rows and non-player casters do not consume per-effect costs.
- Fixed-value VitalModifier rows require the complete conservative build-16042 field shape, an exactly representable signed amount, and a supported vital. Mutations are reconciled against the exact clamped backing value before publishing the actual delta; unsupported formulas, ranges, Breath, no-op results, and unreconciled lifecycle failures drop without a follow-up effect packet. The table's boolean display field is mapped to the client combat-log flag from its build-data shape and client-consumer semantics, pending direct packet-capture confirmation.
- Delayed and periodic spell effects run through one bounded, deterministic timeline with immutable target and phase snapshots, exact-reference aura membership, client cancellation, and build-16042 follow-up packets. Handler, combat-log, and packet failures are isolated without replaying one-shot effects; unsupported apply-prerequisite rows fail closed.
- Property modifiers are owned by exact casting, source-spell, and static-effect identity. Repeated ticks refresh one logical owner, concurrent same-spell casts clean up independently without enabling unsupported stacking, and finite expiry, Aura exit, death, cancellation, failure, and disposal cannot erase a surviving owner. Started spells publish one best-effort build-16042 finish only after modifier and proc cleanup has completed; pre-start failures and direct disposal do not invent one.
- The exact build-16042 all-zero `ResourceRegenMultiplier0` effect shape is retained as multiplicative zero, suppressing endurance regeneration for sprint and the other eleven matching spells without generalising unknown zero-valued semantics across unrelated properties. Exact-owner removal restores the surviving or base multiplier, and time spent suppressed does not bank regeneration catch-up.
- Effect-apply prerequisites composed entirely of valid Level, supported Vital, table-backed BaseFaction, canonical InCombat, strict Boolean DeadState, exact runtime IsPlayer, and absolute current-health components are re-evaluated for the caster and each target at every actual activation before effect-cost admission. Malformed or mixed predicates, dynamic evaluation failures, and persistence/suspend lifecycle rows cannot consume costs, run handlers, or emit follow-up effects; Aura targets can become eligible on a later occupancy scan.
- Absolute `HealthRequirement` components compare the unit's current unsigned health directly with all six canonical numeric operators and require an unused zero object field. Five complete build-16042 rows are now unit-evaluable; percentage-health type 40, `MaxHealth`, and the three mixed type-80 rows remain outside this boundary.
- Raw prerequisite comparison IDs now match both build-16042 client comparator paths exactly: `1 ==`, `2 !=`, `3 >`, `4 >=`, `5 <`, and `6 <=`. Level, Vital, and absolute-health checks share this mapping on their player and unit paths; the previous swapped inclusive/strict ordering for IDs 3–6 is covered by raw-ID regressions.
- Target-cast prerequisites composed entirely of the same unit-safe subset evaluate once against the exact caster for a self target or the currently visible primary unit for player and non-player casts. Supported lookup or evaluation failure returns `PrereqTargetCast` before persistence, conditions, cooldowns, vitals, start packets, or effects; unsupported, missing, malformed, and mixed rows preserve legacy cast behaviour as a whole rather than partially applying a supported component.
- Spell-level caster and target persistence composed entirely of the same unit-safe prerequisite subset is checked before admission and before and after every valid active update. Supported false or exceptional evaluations terminate through owned-effect cleanup before one finish; explicit targets retain exact reference, visibility, liveness, and map authority. Unsupported build rows preserve their prior lifetime rather than broadly disabling 1,297 spells whose persistence semantics are not yet implemented, and UnderSpell remains gated until complete target-side applied-effect ownership exists.
- All 1,407 effect-level persistence/suspend rows across 957 spells remain closed before registration, cost, handler, or publication. The client proves that the five lifecycle prerequisite fields are retained, but not whether a false transition terminates, removes one row, or suspends and later resumes it; all 26 suspend rows also use unsupported predicate shapes, so even the homogeneous caster-only subset is not enabled by inference.
- RapidTap and ChargeRelease roots validate and snapshot their complete build-16042 threshold rows before admission. Exact child references retain immutable target and spell lineage; parent costs commit once, cumulative threshold costs consume atomically, malformed or unsupported child graphs fail closed, and child-start, packet, cancellation, and cleanup failures cannot replay a stage or strand the parent.
- Global cooldown admission is isolated by the build-16042 unsigned lane on every supported cast owner. Sparse lanes expire independently, invalid durations fail before mutation, legacy callers remain on lane zero, and threshold children inherit their root transaction without checking or committing a second lane.
- Spell admission enforces the exact build-16042 caster-out-of-combat and living-primary-target condition rows only when the complete caster, target, and crowd-control tuple is proven supported. Caster failure wins before target lookup; missing and dead targets return their precise cast results before cooldown, vital, start, or effect work. Any movement, taxi, sprint, mixed, malformed, or nonzero crowd-control companion preserves legacy behaviour for the whole spell rather than being partially enforced.
- Normal dash input decodes the complete three-bit direction field, maps only the four build-16042 directions to their exact spell transactions, and rejects every reserved value before casting. The handler delegates resource validation and typed lane-three cooldown admission to the spell pipeline and neither subtracts vitals nor fabricates displacement; `SpellCounter` and the remaining caster, target, and crowd-control condition rows remain gated fidelity work.
- Client-side interactions now use the live build-16042 start/result loop with authoritative cast timing, bounded spatial revalidation, prerequisite-aware activation selection, exactly-once callbacks, and non-disconnecting handling for duplicate, late, and server-data failure paths.
- Chair interactions resolve one exact visible entity, reuse the finite same-map table-range validator, and require the build-16042 chair activation flag before changing state. Unsit commits authoritative state first and independently contains both release publications, so chair visibility loss and player map removal always reach base cleanup. The packet's `Remove` bit and multi-occupant ownership remain gated pending protocol evidence.
- Quest communicator conditions, story-only delivery, idempotent mentions, and callback pickup/hand-in gates are validated against build-16042 data. The client communicator action remains disabled until its one-bit action semantics can be verified from client code or captures.
- Persisted quest countdowns retain build-16042 millisecond semantics, tick only while accepted, and fail closed on missing or corrupt state. Repeat completion calculates a strictly future UTC boundary for daily, weekly, monthly, and yearly periods before reward mutation; missing or unknown reset metadata cannot unlock another completion.
- Group quest sharing uses a server-correlated ten-second offer bound to stable character identity, reciprocal visibility, map, and group state. Forged, stale, replayed, capacity-unsafe, unsupported-contract, or undelivered offers fail closed, and admitted pushed-item faults still bind exactly one quest rather than permitting duplicate grants.
- Inventory acquisition reports one CollectItem event with the actual committed delta after each grant call, including partial grants and mutations whose client packet fails; load, move, split, deletion, consumption, and non-inventory paths do not forge progress. Final quest completion fans out only after the source is committed outside the active set, revalidates observer identity, and isolates observer failures before achievement dispatch.
- Character-currency acquisition reports one EarnCurrency event from the actual committed positive delta after each add call. Caps, zero changes, subtraction, load, pre-mutation packet failure, and overflow cannot forge progress; a post-mutation packet failure still reports the committed grant without replacing the original exception.
- QuestAdvanceObjective effects apply their build-16042 raw amount to one exact active objective slot on the selected player target. Immediate CSI activations suppress only the exact static ActivateEntity objective already advanced by the spell, preserving unrelated and sequential objective batching; callback and packet failures cannot replay committed progress, and late delayed effects cannot retroactively alter a terminal interaction.
- Generic quest objective fanout takes one `(questId, reference)` snapshot per event, revalidates each active identity before dispatch, and contains one quest's failure without starving later observers. Within a quest, mutation and script failures cannot suppress later matching objectives, changed-objective packets are still attempted in ascending order, and achieved state remains dirty and replay-resistant even if its callback or packet publication fails.
- Difficulty-based kill objectives receive the validated `Creature2Difficulty` row of each defeated creature and apply their build-16042 inclusive minimum threshold without changing ordinary exact-target matching. Credit remains limited to unique visible threat participants, duplicate death transitions cannot replay it, and the operator kill command uses the same validated translation.
- World servers retain deeply immutable, validated, revisioned group snapshots from internal group events, reject stale, conflicting, malformed, or invalid-removal updates, and linearise disband against local publication. Persisted producer revisions and bounded local revision barriers prevent delivered-state regression, but they do not prove freshness, completeness, or incarnation across restarts and group-ID reuse; the cache therefore remains preparatory and cannot be the sole group-loot authority.
- GroupServer producer coverage exercises the concrete group, member, character, repository, and outbox publisher paths for add, remove, disband, promotion, settings, member flags, and ready checks. Checked zero/overflow guards, no-op revisions, multi-step promotion ordering, and the serialised queued revision are proven without external I/O. A separate shared-connection SQLite gate loads two stale concrete contexts through the public operation, commits one winner, observes an actual loser outbox insert before the concurrency failure, and proves the default transaction rolls that insert back. It does not validate MySQL migration DDL, unsigned-range handling, locks, isolation, or deadlocks.
- The reactive AI pilot is restricted to the explicit Ravenok 33932 and Scrab 24054 profiles, uses deterministic threat ties and one structurally supported normal attack per creature, and isolates target, threat, movement, and rotation cleanup across death, disable, remove/re-add, and collectible-script reload. Direct paths are calculated and finite-validated before movement mutation; the possibly partial spline-launch sequence is pre-owned, exceptions are contained, and failed cleanup retains a retry gate that prevents recast or relaunch. Scrab uses only inferred auto-attack 65785 at its table-defined 10-metre range and a documented provisional cadence; alternate attack 65786, proactive aggression, and spline ownership remain disabled. Direct movement paths are horizontally segmented with bounded terrain sampling and finite endpoint finalisation.

- Personal-residence privacy changes require the exact owner and exact non-null residence-map reference, accept only Public or Private, and update the public visit index idempotently before returning the authoritative housing basics. Loaded corrupt values fail closed; non-owners can visit only a live Public target, with denial occurring before map-lock, entrance, rotation, or teleport side effects. Neighbour and roommate authority are deliberately not inferred.

- Command help applies the same permission result at its root entry point and every listed handler, preserving the generic unknown-or-unauthorised response against command scraping. Alias keys that share one handler are reference-deduplicated after deterministic ordinal ordering, so all transports receive one stable help entry without changing invocation aliases or permissions.
- Command leaves consume exactly their reflected fixed parameter list. Scalar and quoted-string converters, three-token vectors, and optional parameters retain their declared forms, while any remaining token returns `InvalidParameters` before reflective invocation; no registered converter or command exposes a variadic contract.
- All command ingress now shares one tokenizer that collapses Unicode whitespace only outside quoted strings, preserves whitespace inside them, distinguishes omission from an explicit empty string, and decodes only escaped quotes and backslashes. - Numeric command conversion is invariant across host cultures. Byte, unsigned-short, unsigned-int, and signed-int retain the canonical integer grammar and bounds; float and every vector component accept invariant decimals/exponents only and reject `NaN`, infinities, and finite-text overflow. - Converter and reflected command exceptions are logged server-side with only the declaring handler identity. Console, in-game, and WebSocket contexts receive one existing generic error without stack traces or inner exception data, and the command loop remains available for subsequent work.
- The offline archive reader is maintained in-tree against SharpCompress `0.50.4`; malformed and truncated archives fail closed, and a compressed build-16042 `World.tbl` read was verified byte-for-byte against the extracted client table. The full solution currently reports no vulnerable direct or transitive packages.
